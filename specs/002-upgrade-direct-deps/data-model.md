# Data Model: 升级直接依赖至最新版本

本功能不引入运行时数据或持久化存储。以下实体用于描述升级决策过程与追溯记录，落盘形式为 `build.zig.zon` 与 `README.md` 中的 Markdown 表格。

## 直接依赖 (Direct Dependency)

**来源**：`build.zig.zon` 的 `.dependencies` 表中显式声明的每一项。

| 字段 | 说明 | 校验规则 |
| --- | --- | --- |
| 名称 | 依赖键，如 `jolt`、`imgui` | 与 `.dependencies` 中的键一致，不遗漏、不新增 |
| 来源类型 | tag / 提交 / 分支固定提交 | 必须为不可变引用；禁止分支名或浮动 tag |
| 当前版本标识 | tag 名或提交 SHA | 与当前 `build.zig.zon` 记录一致 |
| 当前内容哈希 | `hash` 字段值 | 固定值，来自 `zig fetch` |
| 上游最新版本 | 官方仓库 API 查询结果 | 需记录查询日期与来源 |
| 兼容性判定 | 可升级 / 保持原样 | 必须给出理由；仅「兼容且通过门禁」才判定可升级 |
| 最终结论 | 新版本标识 / 保持原样 | 与门禁实际结果一致 |

**状态流转**：

```text
待盘点 → 已盘点（记录当前版本与上游最新）
       → 候选升级（存在更新且初步判定兼容）
       → 已升级（新版本 + 新哈希）或 保持原样（附理由）
       → 已验证（通过全部门禁）→ 已记录（README 留痕）
```

**失败分支**：任一门禁失败 → 回退到最后通过门禁的版本 → 状态改为「保持原样（门禁失败）」并记录失败项。

## 验收门禁 (Acceptance Gate)

**来源**：项目既有测试步骤，定义于 `build.zig`，详见 `contracts/acceptance-gates.md`。

| 字段 | 说明 |
| --- | --- |
| 名称 | 门禁可读名称 |
| 命令 | 可复现的命令 |
| 范围 | 覆盖的测试或构建路径 |
| 结果 | 通过 / 失败（失败需记录原因） |

门禁集合固定为五项：核心测试、ReleaseSafe 复测、物理测试、2D 模式独立测试、清屏模式独立测试；另加离线干净构建作为发布条件。

## 升级记录 (Upgrade Record)

**落盘位置**：`README.md`「技术栈与依赖」章节的表格或紧随其后的说明。

| 字段 | 说明 | 校验规则 |
| --- | --- | --- |
| 依赖名称 | 与直接依赖实体一致 | 一一对应，不遗漏 |
| 原版本 | 升级前标识 | 与初始 `build.zig.zon` 一致 |
| 新版本 | 升级后标识，或「保持原样」 | 与最终 `build.zig.zon` 一致 |
| 理由 | 升级收益或不升级原因 | 必须包含兼容性或门禁判定依据 |

**关系**：一个直接依赖对应至多一条升级记录；每条升级记录必须通过全部验收门禁后才可标为「已验证」。

## 校验规则汇总（来自 FR）

- FR-001：依赖集合必须完整覆盖 `.dependencies` 的键。
- FR-003/FR-004：升级后每项必须是精确版本/提交 + 固定哈希，浮动引用数量为 0。
- FR-005：Zig 0.17.1 与 `@compileError` 校验不得修改。
- FR-006：无兼容更新者保持原样，且必须填写理由。
- FR-007/FR-008：记录标记为「已验证」前，全部门禁与离线干净构建必须通过。
- FR-010：不得改变支持边界、物理/相机不变量与缓存语义。
